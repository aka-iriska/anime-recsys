## E01. Baseline'ы: случайный и по популярности

**Стадия:** baseline'ы на уровне retrieval (без отдельного ранжирования).

**Гипотеза и вывод:** в ноутбуке `notebooks/02_baselines.ipynb`.

**Данные и разбиение:** `data/processed/interactions_v0`, собран `src/shikimori_rec/interactions/prepare.py` (`seed=42`). Каталог 6198 аниме (типы `tv`, `movie`, `ova`, `ona`, `special`, `tv_special`; не меньше 5 `completed` у train-пользователей). Основной позитив — `status == 'completed'`. Пользователи разделены по группам: train 1649, val 173, test 172; у val/test 20% позитивов спрятано в `target`. Оценка на **val**, тест не использовался. Кандидаты: каталог без всего, что пользователь уже знает (`*_input`).

**Что запускали:** `uv run python -m shikimori_rec.retrieval.popularity` (или `notebooks/02_baselines.ipynb`).
- `random`: случайный порядок кандидатов, `seed=42`.
- `popularity`: число разных train-пользователей с `completed` на аниме, одинаково для всех.

**Метрики (val, 173 пользователя):**

Ограничения: val содержит 173 пользователя, малые различия между моделями могут быть шумом; доверительные интервалы (bootstrap по пользователям) ещё не считались.

## E02. Item-item по совместному просмотру (бинарное `completed`)

**Стадия:** retrieval (пока упорядочивает весь каталог).

**Гипотеза и вывод:** в ноутбуке `notebooks/03_item_knn.ipynb`.

**Данные и разбиение:** те же, что в E01 (`interactions_v0`, каталог 6198 аниме, оценка на val, 173 пользователя). Матрица «пользователь × аниме» по 1649 train-пользователям, значение 1, если статус `completed`.

**Что изменили относительно E01:** модель по сходству аниме. Сходство пары — взвешенное число общих зрителей, делённое на корень из произведения взвешенных аудиторий (косинус). Вес пользователя `1/n` (`n` — число его `completed`), чтобы активные пользователи не определяли сходство (топ-1% train-пользователей даёт 35% всех пар совместных просмотров). Балл кандидата — сумма его сходств с `completed` из `input`-истории пользователя; уже виденное (любой статус из `input`) исключено. Код: `src/shikimori_rec/retrieval/item_knn.py`, ноутбук: `notebooks/03_item_knn.ipynb`.

**Метрики (val, 173 пользователя, вес `1/n`):**

| | popularity | item_knn |
| --- | ---: | ---: |
| recall@10 | 0,1071 | 0,1527 |
| recall@20 | 0,1680 | 0,2192 |
| hit_rate@10 | 0,7977 | 0,8728 |
| hit_rate@20 | 0,8728 | 0,9480 |
| ndcg@10 | 0,3140 | 0,3988 |
| ndcg@20 | 0,2886 | 0,3656 |
| coverage@10 | 0,0095 | 0,0326 |
| coverage@20 | 0,0165 | 0,0492 |

Критерий успеха (`ndcg@10` ≥ 90% от популярности и `coverage@10` ≥ в 10 раз больше): точность выполнена, покрытие нет (0,0326 против нужных 0,095, то есть рост в 3,4 раза).

**Подбор формы веса пользователя (на val, остальное то же):**

| | `1/n` | `1/sqrt(n)` | `1/log(1+n)` |
| --- | ---: | ---: | ---: |
| hit_rate@10 | 0,8728 | 0,8902 | 0,8671 |
| recall@10 | 0,1527 | 0,1600 | 0,1566 |
| ndcg@10 | 0,3988 | 0,4263 | 0,4133 |
| coverage@10 | 0,0326 | 0,0279 | 0,0279 |


Ограничения: val 173 пользователя, разницу между формами веса (`ndcg@10` 0,399 против 0,426) без доверительных интервалов считать значимой нельзя; форма веса подобрана на val, итоговая оценка должна быть на test.

Дополнение (`k=100`, вес `1/n`): `recall@100` 0,4608, `hit_rate@100` 0,9827, `ndcg@100` 0,3890, `coverage@100` 0,1379 (у популярности 0,3844 / 0,9827 / 0,3069 / 0,0576).

## E02c. Поправка на популярность в баллах item-item

**Стадия:** retrieval (поправка внутри баллов модели).

**Гипотеза и вывод:** в ноутбуке `notebooks/03_item_knn.ipynb`.

**Данные и разбиение:** те же, что в E01/E02 (val, 173 пользователя, каталог 6198 аниме).

**Что изменили относительно E02:** балл кандидата делится на размер его аудитории (число train-пользователей с `completed`) в степени `alpha`. Вес пользователя `1/n`, всё остальное как в E02. Параметр `alpha` подбирается на val. Код: `make_item_knn_ranker(..., audience, alpha)` в `src/shikimori_rec/retrieval/item_knn.py`, ноутбук: `notebooks/03_item_knn.ipynb`, раздел E02c.

**Метрики (val, вес `1/n`):**

| 0,10 | 0,3785 | 0,8902 | 0,4596 | 0,0495 | нет |
| 0,15 | 0,3566 | 0,9017 | 0,4503 | 0,0650 | нет |

## E04. PureSVD: эмбеддинги аниме из усечённого сингулярного разложения

**Стадия:** retrieval. Главная метрика `recall@100`, остальные бонус.

**Гипотеза и вывод:** в ноутбуке `notebooks/04_retrieval_comparison.ipynb`.

**Данные и разбиение:** те же, что в E01–E02c (val, 173 пользователя, каталог 6198 аниме, матрица по 1649 train-пользователям, значение 1 при `completed`).

**Что изменили относительно E02:** вместо матрицы сходства 6198 × 6198 хранятся векторы аниме длины `k`: первые `k` правых сингулярных векторов матрицы «пользователь × аниме» (`scipy.sparse.linalg.svds` по разреженной матрице). Строки матрицы перед разложением умножены на корень из веса пользователя; вес `1/sqrt(n)`. Вектор пользователя из val/test считается проекцией его `input`-истории (сумма векторов просмотренных аниме) без переобучения; балл кандидата — скалярное произведение. Код: `src/shikimori_rec/retrieval/svd.py`; сравнение с интервалами: `notebooks/04_retrieval_comparison.ipynb`.

**Метрики (val, вес `1/sqrt(n)`):**

| | popularity | item_knn | svd k=16 | svd k=32 | svd k=64 | svd k=128 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| **recall@100** | 0,3844 | 0,4777 | 0,5786 | 0,5919 | **0,6181** | 0,6196 |
| hit_rate@100 | 0,9827 | 0,9884 | 0,9942 | 0,9884 | 0,9942 | 0,9884 |
| recall@10 | 0,1071 | 0,1600 | 0,2100 | 0,2282 | 0,2442 | 0,2475 |
| ndcg@10 | 0,3140 | 0,4263 | 0,5311 | 0,5656 | 0,6160 | 0,6320 |
| coverage@10 | 0,0095 | 0,0279 | 0,0432 | 0,0534 | 0,0663 | 0,0773 |
| coverage@100 | 0,0576 | 0,1221 | 0,1815 | 0,2060 | 0,2373 | 0,2678 |


Ограничения: val 173 пользователя; интервалы и парное сравнение моделей вынесены в `notebooks/04_retrieval_comparison.ipynb` (после реализации `bootstrap_ci` в `src/shikimori_rec/evaluation/`); `k` и форма веса подобраны на val; SVD без нормировки на популярность, первый фактор обычно отражает популярность, поэтому покрытие и разнообразие нужно проверять отдельно.

## E04b. PureSVD с нормировкой столбцов на популярность

**Стадия:** retrieval.

**Гипотеза и вывод:** в ноутбуке `notebooks/04_retrieval_comparison.ipynb`, раздел E04b.

**Что изменили относительно E04:** столбцы матрицы (аниме) умножены на `1/аудитория^beta` перед разложением; историю пользователя при подсчёте баллов масштабируем так же. `beta=0,5` соответствует косинусной нормировке из item-item. Код: `column_scale` и параметр `scale` в `src/shikimori_rec/retrieval/svd.py`.

**Метрики (val, `k=64`, вес `1/sqrt(n)`):**

| | без нормировки | `beta=0,25` | `beta=0,5` |
| --- | ---: | ---: | ---: |
| **recall@100** | 0,6181 | 0,6188 | 0,4848 |
| coverage@100 | 0,2373 | 0,3527 | 0,6004 |
| coverage@10 | 0,0663 | 0,0889 | 0,1325 |
| ndcg@10 | 0,6160 | 0,5545 | 0,3148 |

Парное сравнение с обычным SVD по `recall@100`: `beta=0,25` +0,001 [−0,013; 0,015] (не значимо), `beta=0,5` −0,133 [−0,165; −0,104] (значимо).

## E05. ALS для неявной обратной связи (`implicit`)

**Стадия:** retrieval.

**Что изменили относительно E04:** вместо SVD — ALS (Hu, Koren, Volinsky): просмотр (`completed`) считается позитивом с уверенностью `alpha` (бинарная матрица, все просмотры весят одинаково), пустые клетки — «неизвестно» с базовой уверенностью. Регуляризация 0,01, 15 итераций. Вектор val-пользователя считается по его `input`-истории (`recalculate_user`), без переобучения. Код: `src/shikimori_rec/retrieval/als.py`.

**Подбор на val (`factors=64`):** бинарная уверенность лучше `1/sqrt(n)` при `alpha` 1 и 5; лучшее `recall@100` у бинарной при `alpha=5` (0,633), `alpha=20` уже хуже (0,620). Регуляризация 0,01 и 1,0 почти не различаются.

**Метрики (val, `alpha=5`):**

| | svd_k64 | als_f32 | als_f64 | als_f128 |
| --- | ---: | ---: | ---: | ---: |
| **recall@100** | 0,6181 | 0,6140 | 0,6327 | **0,6465** |
| ndcg@10 | 0,6160 | 0,5274 | 0,5688 | 0,5976 |
| coverage@100 | 0,2373 | 0,2502 | 0,2764 | 0,3049 |

Парные сравнения по `recall@100`: `als_f128 − svd_k64` +0,028 [0,016; 0,042], `als_f64 − svd_k64` +0,015 [0,002; 0,028] — значимы. По `ndcg@10` `als_f128 − svd_k64` −0,018 [−0,041; 0,003] — не значимо.

Ограничения: `alpha`, `factors` и вид уверенности подобраны на val; выигрыш над SVD небольшой (около 3 п.п.), нужна проверка на test.
