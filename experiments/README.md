## E02. Item-item по совместному просмотру (бинарное `completed`)

**Стадия:** retrieval (пока упорядочивает весь каталог).

**Гипотеза:** _(напиши сама)_

**Данные и разбиение:** те же, что в E01 (`interactions_v0`, каталог 6198 аниме, оценка на val, 173 пользователя). Матрица «пользователь × аниме» по 1649 train-пользователям, значение 1, если статус `completed`.

**Что изменили относительно E01:** модель по сходству аниме. Сходство пары — взвешенное число общих зрителей, делённое на корень из произведения взвешенных аудиторий (косинус). Вес пользователя `1/n` (`n` — число его `completed`), чтобы активные пользователи не определяли сходство (топ-1% train-пользователей даёт 35% всех пар совместных просмотров). Балл кандидата — сумма его сходств с `completed` из `input`-истории пользователя; уже виденное (любой статус из `input`) исключено. Код: `src/item_knn.py`, ноутбук: `notebooks/03_item_knn.ipynb`.

**Метрики (val, 173 пользователя, вес `1/n`):**

| | popularity | item_knn |
| --- | ---: | ---: |
| recall@10 | 0,1071 | 0,1527 |
| recall@20 | 0,1680 | 0,2192 |
| hit_rate@10 | 0,7977 | 0,8728 |
| hit_rate@20 | 0,8728 | 0,9480 |
| ndcg@10 | 0,3140 | 0,3988 |
| ndcg@20 | 0,2886 | 0,3656 |
| coverage@10 | 0,0095 | 0,0326 |
| coverage@20 | 0,0165 | 0,0492 |

Критерий успеха (`ndcg@10` ≥ 90% от популярности и `coverage@10` ≥ в 10 раз больше): точность выполнена, покрытие нет (0,0326 против нужных 0,095, то есть рост в 3,4 раза).

**Подбор формы веса пользователя (на val, остальное то же):**

| --- | ---: | ---: | ---: |
| hit_rate@10 | 0,8728 | 0,8902 | 0,8671 |
| recall@10 | 0,1527 | 0,1600 | 0,1566 |
| ndcg@10 | 0,3988 | 0,4263 | 0,4133 |
| coverage@10 | 0,0326 | 0,0279 | 0,0279 |
